### Deployment
The application is packaged using Docker, ensuring a consistent deployment across different environments.
The application is built into a single Docker image that includes both the Angular client and the Spring Boot server.
Docker Compose is used to coordinate the required services.
The images are published through continuous integration in three possible ways:

- Manual Build Workflow: Allows a developer to create an image whenever they choose.
- Publish dev on main Workflow: Triggered when a branch is merged into main via a pull request.
- Publish on Release Workflow: Triggered when a release is published.

The final application artifact is published on DockerHub, from where it can be downloaded and executed directly:

- DockerHub repository URL: [DockerHub Repository](https://hub.docker.com/repositories/victorbartolome)

#### Deployment in External Environment
The final release of this project is deployed in an environment different from the development environment.

To achieve this, a virtual machine provided by the URJC was requested, accessible via SSH with the following details:

- **Machine Name**: quesos-bartolome
- **Assigned IP**: 193.147.60.45
- **SSH Access**: ssh vmuser@quesos-bartolome.tfg.etsii.urjc.es
- **Main User**: vmuser (with passwordless sudo permissions)
- **CSR and KEY Files**: Required to request the TLS certificate, available in /home/vmuser/

A private key was also provided to access the machine:
```bash
ssh -i PRIVATE_KEY vmuser@quesos-bartolome.tfg.etsii.urjc.es
```
##### TLS Configuration and Deployment
Once connected to the virtual machine, Docker was installed:
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install docker.io docker-compose git -y
sudo usermod -aG docker vmuser
```

Then, a `certs/` folder was created to store the `.pem` and `.key` files generated by the URJC services.

After that, a `quesos-bartolome` folder was created, where the `.env` file was added.
The docker-compose file was obtained from the Docker image using the following commands:

```bash
docker pull victorbartolome/quesosbartolome:latest
docker pull victorbartolome/quesosbartolome-compose:latest

docker create --name temp-compose victorbartolome/quesosbartolome-compose:latest /bin/sh
docker cp temp-compose:/docker-compose.yml ./docker-compose.yml
docker rm temp-compose
```
With the image and docker-compose ready, Nginx was configured using the following `nginx.conf`:

```bash
events {}

http {
    server {
        listen 80;
        server_name quesos-bartolome.tfg.etsii.urjc.es;
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl;
        server_name quesos-bartolome.tfg.etsii.urjc.es;

        ssl_certificate /etc/nginx/certs/quesos-bartolome.tfg.etsii.urjc.es.pem;
        ssl_certificate_key /etc/nginx/certs/quesos-bartolome.tfg.etsii.urjc.es.key;

        location / {
            proxy_pass https://app:443;
            proxy_ssl_verify off;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
}
```
Finally, running:

```bash
docker-compose up -d
```
The application was successfully deployed and is accessible at:

https://quesos-bartolome.tfg.etsii.urjc.es/cheeses

With a valid certificate and full system functionality.
